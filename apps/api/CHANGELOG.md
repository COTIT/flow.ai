# Changelog

## Unreleased

- Member offboarding (`docs/api/users.md`; no migration): `DELETE /workspace/{workspace}/users/{user}` (`users_remove`, owner or `workspace_admin`) ends a member's access in one transaction. The membership turns inactive so agent and manager links and all authored history stay. The person leaves this workspace's teams, loses farm roles here, and their assistant sessions here close with pending actions cancelled. Logins are deleted only when no other access is left. Removing yourself or the owner returns 409. Accepting a new invite reactivates the membership with only the invite's team. `invites_send` and `teams_list` summaries now say a team is the person's role, so voice tool search finds them.

- Assistant batch prepare latency (no migration): boot `warm_up` now builds the assistant operation inventory (the OpenAPI spec walk behind `resolve_operation`), so the first proposal, batch or guarded dispatch after a deploy no longer pays for it. Local debug build, 10-step batch: 914 ms cold, of which 737 ms was that build; 154 ms warm. Debug-level `tracing` spans now cover batch create, each step's review-fact capture and the batch SQL. Measured per step: two statements, no N+1, no missing index.

- `GET /workspace/{workspace}/assistant/sessions/{session}?with=identity` (`docs/api/assistant.md`; no migration) adds `identity` `{workspaces, permissions, farm_roles}` to the session, matching `/me/workspaces`, this workspace's `/me` permissions and `/farm/me` roles. Office's voice bridge can replace four round trips with one. The request runs three statements in total (token, membership, one session-and-identity read) and caches nothing. Any other `with` value returns 422. The plain `GET` is unchanged.

- Assistant business drafts refuse exact PIN fields recursively before persistence, while ordinary pipeline, shipping and fingerprint fields retain their existing behavior. Till credential changes stay in secure forms.

- Assistant app-key revocation accepts exact reviewed DELETE requests with native admin authorization; key issuance and credential paths keep their secure-form refusal. Revocation returns no credential and consumes approval once.

- Assistant refund receipts remain queued until authoritative native settlement, with transaction-bound refund correlation and bounded metadata reconciliation. Lost HTTP finalization cannot lose the refund reference or replay transport; late responses preserve terminal proof and paused batches stay stopped. Order-to-invoice reviews bind resolved invoice defaults and require invoice read permission to expose derived billing facts.

- Assistant money reviews bind native product/currency/VAT defaults, inherited variant prices and invoice-create contact/billing/line defaults. Existing native resolvers and transaction locks supply both review and execution values; stale facts refuse before writes. Product decimal precision remains unchanged, write-only review facts stay hidden, and large variant/invoice summaries retain private full-material digests with explicit preview counts.

- Team permission receipts (`docs/api/teams.md`; no migration): creation and permission changes report applied, unapplied and ignored requested entries from their write transaction. Existing statuses, message and grant rules stay intact. Unknown input is count-only; unrelated grants stay private. Assistant partial outcomes stop remaining batch steps.

- Fixed ordered assistant batches (`docs/api/assistant.md`; migration `assistant_batches`): one immutable two-to-ten-step review and independent consent, owner/login/session binding, hashed request-bound controller, ordered claims on existing handlers, and verified acknowledgement before each next action. Disconnect, changed facts, expiry, queued or uncertain outcomes stop remaining work without replay. Batch-aware rollback compatibility is required; ordinary single actions retain their contracts.

- Durable invoice delivery (`docs/api/invoices.md`; migrations `assistant_review_facts`, `invoice_delivery`, `assistant_delivery_indexes`): numbering and a specific delivery job commit together, request/worker claims run once, SMTP fencing precedes transport, and typed send-log evidence reconciles acceptance without resending. Unresolved work blocks snapshot replacement. Additive receipts distinguish accepted, blocked, manual, pending and unknown; assistant mail acceptance is queued, never delivered. Material invoice/order/stock facts reject stale approvals under existing locks; write-only members receive redacted public facts. Resolved receipts expire after 90 days; hourly context cleanup removes up to 100 old cleaned sessions only after every action and remote reference is gone.

- Office manages categories (`docs/api/products.md`, no migration): categories gain `products_count` (live products of any status in it, for "3 products will become uncategorised"); `GET /products` takes `?category_id=<uuid>` (another workspace's id finds nothing, a malformed one is 422); a live category name is unique per workspace, trimmed and case-insensitive, so create and rename answer 422 `The name has already been taken.` (Laravel allowed duplicates; names already stored stay, renaming to its own name or another case of it is fine). The check runs under the category tree's workspace lock.
- Mail transport receipts (`docs/api/messages.md`; no migration): `send-message` keeps `message: "ok"` and adds accepted/blocked/manual/no-recipients status with its send-log id. Profile connection tests report blocked sends truthfully. Assistant action audit retains only typed receipt fields, and reviewed GET profile tests now require/consume the same exact approval as other effects.

- Assistant foundation (`docs/api/assistant.md`; migrations `assistant_actions`, `assistant_upload_limits`, `assistant_upload_metadata`, `assistant_approval_events`): login-bound sessions, short-lived exact business drafts, signed bridge approvals and provider bindings, once-only dispatch claims on existing handlers, conservative unknown outcomes, bounded audit evidence and 90-day resolved retention. Conversation attachments reserve ten lifetime/two concurrent slots, at most 10 MiB each; scheduled Rust cleanup retains remote references until confirmed deletion. Existing requests without assistant action headers keep their current contracts.

- Lot guards (`docs/api/lots.md`, `stock.md`, `supply-chain.md`, `warehouses.md`, `webhooks.md`; no migration):
  - Status rules: released ↔ quarantine, either → recalled; recalled is final (`409 lot_status_final`), and POST can't start a lot recalled. Lots gain `next_statuses`. Each change emits `lot.status_changed`.
  - Recalled or held lots don't move: no stock into a recalled lot (`409 lot_recalled`; write-off and returns stay allowed, quarantine still takes goods in), no packing or dispatch from a recalled or quarantined lot (`409 lot_recalled` / `lot_quarantined`), all under the lot's row lock.

  - Lots packed from it follow down the whole line (own trail row with `meta.because_of`, own event). Receiving workspaces get `supply.source_status_changed` and see the sender's status in `received_from.from_lot_status` and the transfer's `from_lot.status`; their lot is never edited.
  - `GET /products/stocks` returns the real `reserved` and new `available` (was `reserved: 0`).
  - A warehouse or bin holding stock or holds isn't deleted (`409 warehouse_holds_stock` / `bin_holds_stock`).
  - `set-stock-levels` refuses a level below what orders hold, and products that don't track stock.
